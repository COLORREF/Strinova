# 提交规范

提交信息采用以下格式：

```text
<类型>[可选作用域]: <简短描述>

[可选详细描述]

[可选脚注]
```

## 类型

- `feat`：新功能（影响次版本号）
- `fix`：修复 bug（影响修订号）
- `docs`：仅文档修改（如 README）
- `style`：代码格式调整（不影响逻辑，如缩进、空格）
- `refactor`：代码重构（既非新功能也非修复）
- `test`：新增 / 修改测试代码
- `chore`：构建流程、工具配置等修改（不影响业务代码）

## 描述要求

- 简短描述控制在 50 字以内，简洁说明“做了什么”
- 不使用句号结尾
- 详细描述在简短描述不足以说明时补充，换行后开始，写明具体修改点
- 脚注可选，用于补充关联信息

## 示例

```text
docs: 添加提交规范说明

补充提交类型、描述格式与示例，统一后续提交信息风格
```
